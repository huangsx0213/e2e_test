## What I do

- Generate README sections (overview, setup, usage, contributing)
- Create API documentation from code signatures and types
- Write architecture decision records (ADRs)
- Produce usage guides with code examples
- Update existing documentation to reflect code changes

## When to use me

Use this skill when you need to:
- Create or update a README for a project
- Document public APIs and interfaces
- Write ADRs for architectural decisions
- Generate onboarding guides for new contributors
- Keep docs in sync with code changes

## How I work

1. **Analyze code**: Read source files to understand APIs, types, and behavior
2. **Check existing docs**: Review current documentation to identify gaps
3. **Follow conventions**: Match the project's existing doc style and format
4. **Write clearly**: Use plain language, provide code examples, avoid jargon
5. **Keep current**: Ensure docs reflect the actual state of the code

## Documentation principles

- Code examples must be runnable and tested
- Document intent, not just what the code does
- Keep docs close to the code they describe
- Prefer examples over long explanations
- Update docs in the same commit as code changes
